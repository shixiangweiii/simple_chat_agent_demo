# 06 — 传输与流式

## 6.1 传输无关设计

A2UI 协议本身是传输无关的（Transport-Agnostic），定义的是消息格式而非传输机制。支持以下传输层：

| 传输方式 | 适用场景 | 特点 |
|---|---|---|
| **SSE** (Server-Sent Events) | Web 前端实时流 | 单向，HTTP 兼容，自动重连 |
| **WebSocket** | 双向实时交互 | 全双工，低延迟 |
| **A2A** (Agent-to-Agent) | 多 Agent 协作 | 跨信任边界，Agent 间 UI 交付 |
| **AG-UI** | Agent-前端事件流 | 事件驱动，16+ 标准事件类型 |
| **REST** | 简单请求-响应 | 无流式，轮询 |
| **MCP** | Agent 工具调用 | MCP 消息内嵌 A2UI 载荷 |

## 6.2 JSONL 流式格式

A2UI 消息以 **JSONL (JSON Lines)** 格式流式传输：每行一个完整的 JSON 消息，以换行符分隔。

```
{"version":"v0.9","createSurface":{"surfaceId":"booking","catalogId":"restaurant"}}
{"version":"v0.9","updateComponents":{"surfaceId":"booking","components":[{"id":"title","component":"Text","text":{"literalString":"预订餐厅"}}]}}
{"version":"v0.9","updateComponents":{"surfaceId":"booking","components":[{"id":"date","component":"DateTimeInput","value":{"path":"/booking/date"},"enableDate":true}]}}
{"version":"v0.9","updateDataModel":{"surfaceId":"booking","updates":[{"path":"/booking/date","value":"2026-06-10T19:00"}]}}
```

**JSONL 的优势**：

1. **渐进式解析**：每行是完整 JSON，到达即可解析，无需等待消息边界
2. **增量渲染**：组件消息到达即可渲染，无需等完整 Surface
3. **错误隔离**：一行解析失败不影响其他行
4. **LLM 友好**：LLM 可以逐条生成消息，无需构建完整 JSON 树后再输出

## 6.3 渐进式渲染流程

```
时间轴 →

Agent 输出:                        客户端渲染:
├─ createSurface ──────────────→  创建空 Surface 容器
├─ updateComponents (title) ───→  渲染标题 "预订餐厅"
├─ updateComponents (date) ────→  渲染日期选择器
├─ updateComponents (guests) ──→  渲染人数输入
├─ updateComponents (submit) ──→  渲染提交按钮
├─ updateDataModel ────────────→  填充初始数据
│                                  Surface 完整可交互
├─ (用户交互: 修改日期)
├─ updateDataModel ────────────→  更新可用时段
├─ updateComponents (slots) ───→  渲染时段列表
│
├─ (用户点击提交)
├─ updateComponents ───────────→  显示加载状态
├─ updateDataModel ────────────→  更新确认信息
├─ updateComponents ───────────→  显示确认结果
├─ deleteSurface ──────────────→  清理 Surface
```

## 6.4 SSE 传输集成

### 直接 SSE

```
POST /api/a2ui/stream
Content-Type: application/json

{ "message": "订明天19:00两人桌", "sessionId": "abc123" }

→ Response: text/event-stream

data: {"version":"v0.9","createSurface":{"surfaceId":"booking","catalogId":"restaurant"}}

data: {"version":"v0.9","updateComponents":{"surfaceId":"booking","components":[...]}}

data: {"version":"v0.9","updateDataModel":{"surfaceId":"booking","updates":[...]}}
```

### 通过 AG-UI 传输

A2UI 消息可以作为 AG-UI 的 `Custom` 事件类型载荷：

```
→ AG-UI SSE Stream

event: TEXT_MESSAGE_START
data: {"type":"TEXT_MESSAGE_START","messageId":"msg-1","role":"assistant"}

event: TEXT_MESSAGE_CONTENT
data: {"type":"TEXT_MESSAGE_CONTENT","messageId":"msg-1","delta":"正在为您准备预订界面..."}

event: CUSTOM
data: {"type":"CUSTOM","name":"a2ui","payload":{"version":"v0.9","createSurface":{"surfaceId":"booking"}}}

event: CUSTOM
data: {"type":"CUSTOM","name":"a2ui","payload":{"version":"v0.9","updateComponents":{...}}}
```

### B站双通道架构

B站 Vue 渲染器实现了 SSE 双通道：

```
通道 1: 文本聊天流                    通道 2: A2UI Surface 更新
SSE /api/chat                        SSE /api/a2ui
├── TextMessageContent               ├── createSurface
├── TextMessageContent               ├── updateComponents
└── TextMessageEnd                   └── updateDataModel
```

两个通道并行推送，前端同时渲染聊天文本和 A2UI Surface。

## 6.5 客户端 → Agent 通信

### 事件回调

用户交互（点击按钮、提交表单）通过 HTTP POST 发回 Agent：

```
POST /api/a2ui/action
Content-Type: application/json

{
  "surfaceId": "booking",
  "componentId": "submit-btn",
  "event": {
    "name": "confirm_booking",
    "args": {
      "date": "2026-06-10T19:00",
      "guests": "2"
    }
  }
}
```

### v0.9 双向数据同步

v0.9 新增客户端到服务端的 DataModel 自动同步：

```
用户在 TextField 输入 → DataModel 本地更新 → 自动同步到 Agent
                                        ↓
                                  Agent 收到更新后
                                  可以生成新的 surfaceUpdate
                                  或 updateDataModel 响应
```

## 6.6 Agent SDK 流式辅助

v0.9 的 Python Agent SDK 提供流式生成辅助：

```python
from a2ui import AgentSDK

sdk = AgentSDK(catalog_id="restaurant-catalog")

# 自动修复组件属性（补全缺失字段、校验类型）
surface = sdk.create_surface("booking")
surface.add_component("Text", id="title", text="预订餐厅")
surface.add_component("DateTimeInput", id="date", value_path="/booking/date")
surface.add_component("Button", id="submit", child="submit-text", action_name="confirm")

# 流式输出 JSONL
for message in surface.stream():
    print(message)  # 每条消息是完整 JSON 行
```

Agent SDK 的核心功能：
1. **自动修复**：补全缺失的必需属性
2. **Schema 校验**：确保输出符合 A2UI 规范
3. **Prompt 生成**：为 LLM 生成包含 Catalog 约束的 system prompt

## 6.7 与本项目传输层的对照

| A2UI | 本项目 | 差异 |
|---|---|---|
| JSONL 流式 | SSE `(event_name, payload_dict)` 元组 | A2UI 纯 JSONL；本项目带事件名标签 |
| 传输无关 | 仅 SSE | A2UI 更灵活；本项目耦合 SSE |
| 渐进式渲染 | `ui_surface_update` 逐组件推送 | 同构 |
| 客户端 → Agent 事件 | `POST /api/ui_action` | 同构；A2UI 有标准化 schema |
| 双向数据同步 | 单向 | v0.9 支持自动双向；本项目手动 |
| 文本 + Surface 分通道 | 单 SSE 流复用 | B站用双通道；本项目单通道事件复用 |
