# 10 — 实现案例

## 10.1 B站 Vue 渲染器

### 背景

B站 (Bilibili) 商业广告团队基于 A2UI 协议构建了 Vue 渲染器和完整的 Agent 工具链，用于：
- 广告投放助手
- 产品帮助助手
- 数据分析助手

发布时间：2026-05-27

### 架构

```
┌──────────────────────────────────────────────────────┐
│                    Agent 后端                          │
│  Runtime Schema 组装 → 每业务动态组件白名单              │
└────────────────────────┬─────────────────────────────┘
                         │ SSE 双通道
                    ┌────┴────┐
                    │         │
              通道 1: 文本流   通道 2: A2UI Surface
              (TextMessage)   (createSurface + updateComponents)
                    │         │
                    └────┬────┘
                         ▼
┌──────────────────────────────────────────────────────┐
│                  Vue 前端                              │
│  ┌──────────────┐  ┌───────────────────────────────┐ │
│  │ 聊天消息列表   │  │ A2UI Surface 渲染器            │ │
│  │ (文本 + 代码)  │  │ (Vue Wrapper 组件)            │ │
│  └──────────────┘  └───────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

### 关键设计决策

1. **Runtime Schema 组装**：每个业务场景有独立的组件白名单，Agent 只能使用该场景注册的组件
2. **双重验证机制**：
   - **结构验证**：消息类型合法性、组件白名单校验、属性完整性检查、Action 白名单校验
   - **过渡验证**：Surface 状态机一致性检查（未创建的 Surface 不能更新、不能重复创建等）
3. **SSE 双通道输出**：文本聊天流和 A2UI Surface 更新并行推送
4. **Wrapper 组件扩展**：业务组件通过 Vue Wrapper 注册到 Catalog，保持 Vue 组件的完整能力
5. **从模板迁移**：从基于模板的方法（`::: ProductCard :::`）迁移到 A2UI 生成式 UI

### 迁移经验

从模板到 A2UI 的迁移动机：
- 模板方法需要预定义所有可能的 UI 模板，扩展性差
- A2UI 允许 Agent 动态组合组件，更灵活
- 但需要更严格的验证机制确保输出可控

### 目录设计教训

B站团队明确建议：**不要把 Catalog 变成"低级组件超市"**

- ❌ 原子原语：Button、Input、Row、Column → Agent 输出不可控，UI 不一致
- ✅ 业务级组件：AddressForm、UserPicker、RefundCard → UI 一致，Agent 输出可预测

## 10.2 Jetpack Compose 渲染器 (a2ui-compose)

### 背景

中国 Android 开发者因 Google 官方 Jetpack Compose 渲染器仍在路线图中，自行实现了开源版本。

发布时间：2026-03-24

### 4 层架构

```
Layer 4: A2UIRenderer (Composable)
  └── 顶层入口，接收 A2UI JSON 并触发渲染
       │
Layer 3: 18 种组件类型
  └── Text, Button, Card, Tabs, Row, Column, List,
      Image, Icon, Divider, TextField, CheckBox,
      DateTimeInput, Slider, Modal, Rating, Video, 自定义
       │
Layer 2: Engine
  ├── SurfaceManager (Surface 生命周期)
  ├── DataModelManager (JSON Pointer 数据管理 + 双向绑定)
  └── FunctionRegistry (14 个内置函数)
       │
Layer 1: Parser + Network
  ├── JSONL 解析器
  ├── SSE 客户端 (OkHttp)
  └── WebSocket 客户端
```

### 关键特性

- **18 种组件**：覆盖 A2UI Basic Components + 扩展
- **14 个内置函数**：`required`、`email`、`formatDate`、`parseNumber` 等
- **DataModelManager**：通过 JSON Pointer 管理组件数据，支持双向绑定
- **Surface 生命周期管理**：创建 → 渲染 → 交互 → 销毁

### 亮点

- 完整实现了 A2UI v0.8 规范
- 在 Google 官方渲染器缺失的情况下填补了 Android 生态空白
- 双向数据绑定使 Compose 原生 UI 响应 A2UI DataModel 更新

## 10.3 鸿蒙 AGenUI

### 背景

高德 (Amap) 地图团队开发的 HarmonyOS (ArkTS) A2UI 渲染器。

发布时间：2026-05-31

GitHub: https://github.com/AGenUI/AGenUI

### 架构

```
┌──────────────────────────────────────┐
│          HarmonyOS (ArkTS)           │
│                                      │
│  ┌────────────────────────────┐      │
│  │ SSE 客户端                  │      │
│  │ (手动 UTF-8 解码 + 协议解析) │      │
│  └────────────┬───────────────┘      │
│               ▼                      │
│  ┌────────────────────────────┐      │
│  │ Surface 生命周期管理         │      │
│  │ (创建 / 更新 / 销毁)        │      │
│  └────────────┬───────────────┘      │
│               ▼                      │
│  ┌────────────────────────────┐      │
│  │ 渲染器                      │      │
│  │ ├── Markdown 组件            │      │
│  │ ├── Chart 组件              │      │
│  │ ├── Lottie 动画组件         │      │
│  │ └── 自定义组件              │      │
│  └────────────┬───────────────┘      │
│               ▼                      │
│  ┌────────────────────────────┐      │
│  │ 聊天消息列表集成             │      │
│  └────────────────────────────┘      │
└──────────────────────────────────────┘
```

### 关键特性

- **SSE 客户端**：在鸿蒙上手动实现 UTF-8 解码和 SSE 协议解析（鸿蒙无原生 SSE 支持）
- **Surface 生命周期**：与聊天消息列表深度集成，Surface 作为消息的一部分展示
- **扩展组件**：除了 Basic Components，还支持 Markdown 渲染、Chart 图表、Lottie 动画
- **跨端适配**：适配鸿蒙特有的 ArkTS 开发范式

### 技术挑战

- 鸿蒙无原生 SSE 支持，需要手动解析
- ArkTS 与 TypeScript 差异较大，渲染器实现需要适配
- Surface 与聊天列表的集成需要处理滚动、布局等复杂交互

## 10.4 阿里千问 + UCP

### 背景

阿里千问应用将 A2UI 与 Google 的 UCP (Universal Commerce Protocol) 结合，实现了中国首个主要的消费者级 AI "做事"助手。

发布时间：2026-01-19

### 生态整合

千问 Task Assistant 连接阿里生态系统服务：

| 服务 | 用途 |
|---|---|
| 淘宝 | 商品搜索、下单 |
| 支付宝 | 支付、转账 |
| 飞猪 | 旅行预订 |
| 高德地图 | 地图导航 |
| 饿了么 | 外卖点餐 |

### 特点

- **不是纯粹的 A2UI 实现**：结合了 UCP 协议和阿里自有技术
- **生态优先**：利用阿里庞大生态，而非构建开放标准
- **消费者级 AI**：面向普通用户，而非开发者
- **中文社区评价**："当 Google 致力于制定标准时，阿里在中国选择了一条更直接的落地路线"

## 10.7 实现经验总结

### 共性经验

1. **双重验证是生产必需**：B站和 a2ui-compose 都实现了结构验证 + 过渡验证
2. **目录设计决定 UI 质量**：业务级组件 > 原子原语
3. **SSE 是最常用的传输**：所有实现都支持 SSE，部分额外支持 WebSocket
4. **Surface 与聊天列表集成**：Surface 不是独立页面，而是聊天消息的一部分
5. **扩展组件**：每个实现都扩展了 Basic Components（Chart、Markdown、Lottie 等）

### 常见挑战

1. **JSON Pointer 实现**：不同语言的 JSON Pointer (RFC 6901) 实现成熟度不一
2. **双向数据绑定**：v0.9 的客户端-服务端数据同步实现复杂
3. **渲染器一致性**：不同框架渲染器间的行为差异需要统一 Web Core
4. **LLM 输出校验**：Agent SDK 的自动修复能力有限，复杂 UI 仍需人工干预

### 对本项目的启示

1. **验证机制**：本项目 `DeclarativeRenderer` 缺少组件白名单验证，可参考 A2UI Catalog
2. **Surface 状态机**：本项目无 Surface 生命周期管理，可参考 B站的过渡验证
3. **业务组件**：本项目只有 6 种基础组件，可考虑注册业务级组件
4. **数据绑定**：本项目无自动数据绑定，组件不响应 DataModel 变化
