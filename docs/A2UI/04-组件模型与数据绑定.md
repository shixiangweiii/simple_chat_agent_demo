# 04 — 组件模型与数据绑定

## 4.1 邻接表组件模型

A2UI 的组件模型采用**邻接表**（Adjacency List）而非嵌套 JSON 树，这是对 LLM 生成特性的关键优化。

### 为什么不用嵌套树？

嵌套 JSON 树在 LLM 生成时面临严重问题：

1. **括号闭合错误**：深层嵌套的 `}` / `]` 容易漏写或多写，LLM 越深越容易出错
2. **无法增量生成**：必须等整个树完整后才能发送和渲染
3. **难以局部更新**：修改一个深层节点需要重发整棵子树

### 邻接表设计

组件以**扁平数组**形式存储，通过 ID 引用建立父子关系：

```json
{
  "components": [
    { "id": "root", "component": "Column", "children": ["title", "form"] },
    { "id": "title", "component": "Text", "text": { "literalString": "预订餐厅" } },
    { "id": "form", "component": "Card", "children": ["date", "guests", "submit"] },
    { "id": "date", "component": "DateTimeInput", "value": { "path": "/booking/date" } },
    { "id": "guests", "component": "TextField", "label": "人数", "value": { "path": "/booking/guests" } },
    { "id": "submit", "component": "Button", "child": "submit-text", "action": { "name": "confirm" } },
    { "id": "submit-text", "component": "Text", "text": { "literalString": "确认" } }
  ]
}
```

**优势**：

| 特性 | 嵌套树 | 邻接表 |
|---|---|---|
| LLM 生成 | 深层括号易错 | 扁平结构，每项独立 |
| 增量渲染 | 必须等完整树 | 组件到达即可渲染 |
| 局部更新 | 重发子树 | 只发变更组件 |
| 流式传输 | 困难 | 天然支持 JSONL |
| 引用关系 | 隐式（嵌套位置） | 显式（ID 引用） |

## 4.2 基础组件目录 (Basic Components)

v0.9 将组件集重命名为 "Basic Components"（不再用 "Standard"），强调这些只是参考/基础组件，客户端可注册自定义组件。

### 布局组件

| 组件 | 属性 | 说明 |
|---|---|---|
| `Row` | `children: string[]`, `alignment?`, `spacing?` | 水平布局 |
| `Column` | `children: string[]`, `alignment?`, `spacing?` | 垂直布局 |
| `List` | `children: string[]`, `itemTemplate?` | 列表容器 |
| `Card` | `children: string[]` | 卡片容器 |
| `Tabs` | `tabs: Tab[]`, `selectedTabPath?` | 标签页 |
| `Modal` | `children: string[]`, `title?` | 模态框 |

### 展示组件

| 组件 | 属性 | 说明 |
|---|---|---|
| `Text` | `text: StringBinding`, `usageHint?` (h1-h5, body, caption) | 文本 |
| `Image` | `source: StringBinding`, `imageVariant?` (icon, avatar, smallFeature, ...) | 图片 |
| `Icon` | `icon: IconEnum` (40+ 图标) | 图标 |
| `Video` | `source: StringBinding` | 视频 |
| `Divider` | 无 | 分割线 |
| `Rating` | `value: NumberBinding`, `maxRating?` | 评分 |

### 交互组件

| 组件 | 属性 | 说明 |
|---|---|---|
| `Button` | `child: string`, `action: Action`, `enabled?` | 按钮 |
| `TextField` | `value: StringBinding`, `label?`, `placeholder?`, `inputType?` | 文本输入 |
| `CheckBox` | `value: BooleanBinding`, `label?` | 复选框 |
| `DateTimeInput` | `value: StringBinding`, `enableDate?`, `enableTime?` | 日期时间选择 |
| `Slider` | `value: NumberBinding`, `min?`, `max?`, `step?` | 滑块 |

### Action 结构

```json
{
  "name": "confirm_booking",
  "args": {
    "source": "booking-form"
  }
}
```

Action 是 Button 点击时触发的事件名称 + 附带参数，客户端封装后发回 Agent。

## 4.3 数据绑定 (Data Binding)

数据绑定是 A2UI 的核心机制，将 UI 结构与应用状态解耦。

### 三种绑定模式

#### 1. 字面值 (Literal)

```json
{ "literalString": "Hello World" }
```

静态值，不随数据变化。适用于标签、标题等固定文本。

#### 2. 路径绑定 (Path Binding)

```json
{ "path": "/booking/date" }
```

通过 JSON Pointer (RFC 6901) 绑定到 DataModel 中的路径。DataModel 更新时，绑定的 UI 组件自动重渲染。

#### 3. 初始化简写 (Initialized Binding)

```json
{
  "literalString": "2026-06-10",
  "path": "/booking/date"
}
```

`literalString` 是初始值，`path` 是后续更新路径。首次渲染显示字面值，后续由 DataModel 驱动。

### DataModel 更新机制

```json
{
  "updateDataModel": {
    "surfaceId": "booking",
    "updates": [
      { "path": "/booking/date", "value": "2026-06-10T19:00" },
      { "path": "/booking/guests", "value": "2" },
      { "path": "/booking/available_slots", "value": ["19:00", "19:30", "20:00"] }
    ]
  }
}
```

DataModel 是一个 JSON 对象，通过 JSON Pointer 路径进行细粒度更新：

- `/booking/date` → 精确到单个字段
- `/booking/available_slots/0` → 精确到数组元素
- `/` → 根替换

### 数据绑定流程

```
Agent 发送 dataModelUpdate → 客户端更新 DataModel
                                    ↓
                            JSON Pointer 匹配
                                    ↓
                    绑定该 path 的组件自动重渲染
```

用户交互时（如在 TextField 输入）：

```
用户输入 → 组件更新本地 DataModel → v0.9: 自动同步回 Agent
                                    ↓
                              UI 即时响应（无需等待 Agent）
```

## 4.4 自定义组件

客户端可注册业务级自定义组件到 Catalog：

```json
{
  "catalogId": "e-commerce",
  "components": {
    "ProductCard": {
      "properties": {
        "productId": { "type": "string" },
        "title": { "type": "StringBinding" },
        "price": { "type": "NumberBinding" },
        "imageUrl": { "type": "StringBinding" },
        "onAddToCart": { "type": "Action" }
      },
      "renderer": "ProductCardRenderer"
    },
    "MetricChart": {
      "properties": {
        "metric": { "type": "string" },
        "data": { "type": "StringBinding" },
        "chartType": { "type": "string", "enum": ["line", "bar", "pie"] }
      },
      "renderer": "MetricChartRenderer"
    }
  }
}
```

**最佳实践**（来自中文社区）：Catalog 应使用**业务/场景级组件**（如 `AddressForm`、`UserPicker`、`RefundCard`），而非原子原语（如 `Button`、`Input`），以确保 UI 一致性和可控的 Agent 输出。

## 4.5 与本项目组件模型的对照

| A2UI | 本项目 | 差异 |
|---|---|---|
| 邻接表 (扁平 ID 引用) | 扁平组件数组 (含 `id="root"`) | 同构；本项目 `children` 是组件 ID 数组 |
| JSON Pointer 数据绑定 | 简化路径写入 (`path` + `value`) | A2UI 更精细；本项目支持根替换和深路径 |
| Basic Components (14 种) | 硬编码 6 种 (text/card/row/column/table/button) | A2UI 组件集更丰富 |
| Catalog 动态白名单 | 无（组件集固定） | A2UI 安全性更强 |
| 字面值 / 路径 / 初始化三模式 | 字面值 + data 对象 | A2UI 绑定更灵活 |
| 自定义组件 | 无 | A2UI 支持业务级组件 |
| 双向数据同步 | 单向 (`/api/ui_action`) | v0.9 支持自动双向 |
