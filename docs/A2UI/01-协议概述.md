# 01 — A2UI 协议概述

## 1.1 定义

**A2UI (Agent-to-UI)**，也称 Agent-to-User Interface，是由 Google 发起的**声明式 UI 协议**。它定义了 AI Agent 如何以标准化 JSON 格式向用户界面描述 UI 组件，而客户端使用其原生框架（React / Flutter / Vue / Compose 等）渲染这些组件。

核心口号：**"Agent 说 UI (JSON), 客户端画 UI (原生组件)"**

- **GitHub**: https://github.com/a2ui-project/a2ui (15.2k stars, 1.2k forks)
- **官网**: https://www.atoui.org/ (规范文档) / https://a2ui.dev/ (开发者门户)
- **许可证**: Apache 2.0
- **当前版本**: v0.8 (稳定, 生产可用) → v0.9 (草案, 2026-04 发布)

## 1.2 解决的核心问题

| 痛点 | 现状 | A2UI 解法 |
|---|---|---|
| 纯文本交互效率低 | 预订餐厅需 10 轮问答，信息密度低 | Agent 生成结构化表单 UI，一轮完成 |
| LLM 生成代码不安全 | 输出 HTML/JS 存在 XSS 注入风险 | 只输出声明式 JSON，客户端原生渲染，无代码执行 |
| 跨平台不一致 | Web/移动/桌面样式割裂 | 同一份 JSON 被 React/Flutter/Compose 原生渲染 |
| 多轮对话体验差 | 每轮都要等 Agent 完整响应 | 支持流式渐进渲染，组件到达即可展示 |

## 1.3 定位：协议规范，非 UI 框架

A2UI **不是** UI 框架或代码生成器，它是一份**协议规范**：

- **不是** React / Vue / Flutter 的替代品
- **不是** HTML/CSS 代码生成器
- **不是** 传输协议（不定义 HTTP/WebSocket 细节）
- **是** Agent 与客户端之间的 UI 通信标准

类比：
- MCP 定义了 Agent 如何调用工具 → A2UI 定义了 Agent 如何描述 UI
- HTTP 定义了请求-响应格式 → A2UI 定义了 UI 更新消息格式

## 1.4 版本演进

| 版本 | 时间 | 关键变化 |
|---|---|---|
| v0.8 (稳定) | 2025-12 首次开源 | 5 种消息：`surfaceUpdate` / `dataModelUpdate` / `deleteSurface` / `callFunction` / `beginRendering`；Lit + Angular 渲染器 |
| v0.9 (草案) | 2026-04 | 消息改为 4 种：`createSurface` / `updateComponents` / `updateDataModel` / `deleteSurface`；新增 `catalogId`；共享 Web Core + React 渲染器；Agent SDK (Python)；客户端自定义函数；客户端-服务端数据同步 |
| v1.0 (计划) | TBD | 稳定化，Go/Kotlin Agent SDK |

### v0.8 → v0.9 关键差异

| 维度 | v0.8 | v0.9 |
|---|---|---|
| Surface 创建 | `beginRendering` + `surfaceUpdate` | `createSurface` (合并) |
| 组件定义 | `"Text": { "text": {...} }` 嵌套对象 | `"component": "Text"` 字符串值 |
| 组件目录 | "Standard Components" | "Basic Components" + `catalogId` 外部目录 |
| 客户端函数 | 无 | 支持 `ClientFunction` |
| 数据同步 | 单向 (Agent → 客户端) | 双向 (客户端操作同步回 Agent) |
| 渲染器 | Lit / Angular | 统一 Web Core + React / Flutter / Angular |
| Agent SDK | 无 | Python SDK (自动修复/校验/prompt 生成) |

## 1.5 Google 生产环境使用

| 产品 | 用法 |
|---|---|
| **Opal** | 服务数十万用户的 AI 小程序平台；A2UI 驱动动态生成 UI |
| **Gemini Enterprise** | 自定义业务 Agent；AI 生成的表单、审批仪表板、工作流自动化 UI |
| **Flutter GenUI SDK** | A2UI 作为 Agent-Flutter 通信的底层协议 |
| **内部 Agent 系统** | 多 Agent 工作流、远程 Agent 支持的标准化 UI 协议 |

## 1.6 在 Agent 协议栈中的位置

| 层 | 协议 | 发起者 | 职责 |
|---|---|---|---|
| Agent ↔ 工具/数据 | **MCP** (Model Context Protocol) | Anthropic (2024-11) | Agent 如何调用外部工具和访问数据源 |
| Agent ↔ Agent | **A2A** (Agent-to-Agent) | Google (2025-04) | Agent 间通信/发现/协作 |
| Agent ↔ 前端(传输) | **AG-UI** | CopilotKit (2025-05) | Agent 与前端的事件流通信 |
| Agent ↔ 前端(UI) | **A2UI** | Google (2025-12) | Agent 如何声明 UI 组件结构 |

四者互补，非竞争：MCP 管"手"（工具），A2A 管"口"（Agent 间），AG-UI 管"管道"（事件传输），A2UI 管"脸"（UI 渲染）。
